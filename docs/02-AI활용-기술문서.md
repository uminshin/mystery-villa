# AI 활용 기술 문서 — 그날 밤, 별장에서

이 문서는 개발 과정에서 AI를 **무엇에, 어떻게** 썼는지와, 그 과정에서 실제로
겪은 실패와 수정을 사실대로 기록한 것이다. 잘된 결과만 적지 않고 헛짚은
과정까지 남긴다. 원인을 모르고 넘어간 것은 그렇게 적었다.

---

## 1. 사용한 AI 도구

| 용도 | 도구 | 비고 |
| --- | --- | --- |
| 게임 런타임 (게임 마스터) | **Claude Opus 5** (`claude-opus-5`) | anthropic SDK 직접 호출. LangChain 등 프레임워크 미사용 |
| 개발 (코드·에셋·문서 작성) | **Claude Code** (Claude Opus 5) | 대화형으로 전체 코드베이스 작성 |
| 이미지 생성 AI | **사용하지 않음** | 삽화는 AI가 SVG 코드를 직접 작성 |
| 음성·음악 생성 AI | **사용하지 않음** | 오디오는 AI가 작성한 신호합성 코드로 생성 |

개발 방식은 **대화형 반복**이었다. 개발자가 요구사항과 플레이테스트 피드백을
주고, Claude Code가 코드를 작성하고 테스트를 돌려 검증하고 원인을 진단했다.
커밋 17개가 그 과정을 그대로 담고 있다.

## 2. 구조 — AI에게 무엇을 맡기지 않았는가

이 프로젝트에서 가장 중요한 설계 결정은 **AI에게 게임 상태를 맡기지 않은 것**이다.

```
┌──────────────────────────────────────────────┐
│  app.py         화면만 그린다. 규칙 판단 없음      │
└───────────────┬──────────────────────────────┘
                │
┌───────────────▼──────────────┐  ┌─────────────────────────┐
│  game_state.py               │  │  gm.py                  │
│  ─────────────               │  │  ─────                  │
│  턴 증가                      │  │  나레이션 생성            │
│  단서 발견 판정                │  │  선택지 3개 제안          │
│  엔딩 분기                    │  │  의심도·신뢰도 델타 제안    │
│  평판 계산                    │  │  변화 이유(비고) 작성      │
│                              │  │                         │
│  순수 함수 · 결정론적           │  │  Claude Opus 5          │
│  Streamlit·API 의존성 없음     │  │  제안만 하고 확정하지 않음   │
└──────────────────────────────┘  └─────────────────────────┘
```

**LLM은 제안만 하고, 확정은 Python이 한다.**

- 턴 증가 · 단서 발견 · 엔딩 분기 · 평판 점수는 전부 `game_state.py`가 결정한다
- LLM이 보낸 의심도·신뢰도 델타는 `±15`로 잘라서 적용한다
- LLM이 이상한 선택지를 보내면 `gm._normalize()`가 걸러내고 결정론적으로 보충한다

이렇게 한 이유는, 엔딩 조건("진범 지목 + 결정적 단서 2개 이상")이 모델 출력에
흔들리면 게임이 성립하지 않기 때문이다. 부수 효과로 `game_state.py`는
Streamlit도 API도 없이 단독 테스트가 된다.

## 3. AI 대상 주요 프롬프트 및 지시 사항

시스템 프롬프트는 약 5,400자다. 매 턴 동일하므로 prompt caching으로 재사용한다.
전문은 `gm.py`의 `build_system_prompt()`에 있다. 핵심 지시만 옮긴다.

### 3.1 역할과 상황

```
당신은 미스터리 텍스트 어드벤처 "그날 밤, 별장에서"의 게임 마스터(GM)다.

플레이어는 손님이 아니라 **의뢰를 받고 섬에 건너온 탐정**이다. 별장에 머무는
세 사람을 상대로 하룻밤 동안 진범을 찾아야 한다. 플레이어를 손님으로 부르지 마라.

피해자: 별장 주인 · 60대 남성
사인: 서재에서 둔기에 의한 후두부 손상
사망 추정 시각: 23:40 전후
```

### 3.2 진범 비공개 — 가장 중요한 제약

```
[비공개 진실]
진범은 C(개인 비서)다.
이 사실을 플레이어에게 직접 말하지 마라. 확정적으로 암시하지도 마라.
마지막 턴까지 A와 B도 그럴듯한 용의자로 남겨두어야 한다.
"범인은 ~다", "~가 죽였다" 같은 단정적 서술은 금지.
단서는 해석의 여지를 남긴 채 묘사한다.
```

GM은 정답을 알아야 서술이 일관되지만, 그것을 흘리면 게임이 끝난다. 이 긴장을
프롬프트로 관리했고, **프롬프트만으로 부족한 부분은 구조로 막았다**(4.4 참고).

### 3.3 공간 규칙 — 평면도와 일치시키기

```
[공간 구조 — 평면도와 일치시켜야 한다]
2층: 다락방, 서재
1층: 거실, 침실
지하: 금고실
옥외: 정원, 창고 (창고는 정원 끝에 붙어 있다)

이동 문구는 이 층 관계에 맞춰라. 같은 층끼리는 "올라간다/내려간다"를 쓰지 말고
"건너간다 / 옆방으로 간다"처럼 쓴다. 정원으로 갈 때는 "밖으로 나간다".
```

플레이테스트에서 같은 층 사이를 "올라간다"고 서술하는 문제가 나와 추가했다.

### 3.4 알리바이 3층 구조 — 반복 심문 설계

15턴이면 같은 인물을 두세 번 심문할 수 있다. 같은 말을 반복하면 플레이어가
턴을 버린 셈이 되므로, 인물마다 내줄 정보를 층으로 나눴다.

```
■ C (개인 비서, 여성 30대)
  1차: 23:00에 방에 들어가 잤고, 00:10에 물을 마시러 나왔다가 시신을 발견했다.
  2차: 그날 저녁 피해자와 단둘이 이야기했다는 것은 인정한다.
       무슨 이야기였는지는 "일정 정리"라고만 하고 넘어간다.
  3차: 관계가 있었다는 것을 인정한다. 다만 "끝난 지 오래됐다"고 말한다
       (거짓이다 — 그날 밤 끝났다).
  약점 1: 비는 23:20에 그쳤다. 정원 발자국이 남으려면 그 이후에 나갔어야 한다.
  약점 2: 창고 정리를 맡은 사람은 그녀다. 선반의 빈 자리를 설명할 수 있는
    사람도 그녀뿐이다.
  이 두 약점은 플레이어가 해당 단서를 찾은 경우에만 지적할 수 있다.
  C는 어떤 상황에서도 살인을 자백하지 않는다.

[심문 규칙]
- 같은 층을 두 번 반복하지 마라. 이미 말한 층은 건너뛰고 다음 층을 내준다.
- 같은 인물을 다시 심문하면 반드시 새 정보를 하나 준다.
- 신뢰도 구간별 태도:
  0~30   적대적. 짧게 자르거나 질문을 되받는다.
  31~69  기본. 해당 층의 내용을 말한다.
  70~100 협조적. 해당 층 + 숨긴 것까지 흘린다.
- 세 사람 모두 거짓말을 한다. 거짓말한다는 사실만으로 범인을 가릴 수 없어야 한다.
```

실제 API로 C를 세 번 연속 심문해 검증했다.

| 차수 | 나온 정보 | 비고 필드 | 의심도 |
| --- | --- | --- | --- |
| 1차 | 취침 주장 + 공백을 스스로 인정 | `23시~00시10분 공백 확인` | +5 |
| 2차 | 단둘이 대화한 것 인정, 내용은 얼버무림 | `대화 내용을 얼버무림` | +4 |
| 3차 | 관계 인정, "끝난 지 오래됐다"(거짓) | `피해자와의 관계를 뒤늦게 인정` | +8 |

3차 나레이션 실제 출력:

> 세 번째로 같은 자리에 앉히자 C의 목소리가 조금 낮아진다. "그분과 저는… 그런
> 관계였던 적이 있어요. 하지만 끝난 지 오래됐습니다." 오래됐다는 말을 할 때
> 그녀의 시선이 찻잔 바닥으로 떨어졌다가 곧 되돌아온다.

### 3.5 플레이어가 모르는 정보 금지

플레이테스트에서 "아직 찾지도 않은 단서를 언급하는 선택지"가 나왔다.
나쁜 예를 함께 넣어 교정했다.

```
- **선택지 문구는 플레이어가 이미 아는 것만으로 써라.**
  브리핑에서 공개한 정보와 지금까지 발견한 단서, 이전 나레이션에서 실제로
  서술한 내용만 쓸 수 있다.
  - 나쁜 예: "금고실의 위조 계약서를 확인한다" (아직 찾지 못한 단서를 언급)
  - 나쁜 예: "B의 채무 액수를 캐묻는다" (심문으로 나온 적 없는 정보)
  - 좋은 예: "금고실로 내려가 본다", "B에게 어젯밤 행적을 묻는다"
  확신이 서지 않으면 "둘러본다 / 말을 걸어 본다"처럼 일반적인 문구를 써라.
```

### 3.6 수치 변화의 근거 남기기

"의심도가 왜 올라갔는지 모르겠다"는 피드백을 받아 응답 스키마에 필드를 추가했다.

```
- change_note: 수치가 왜 움직였는지 25자 이내로 적어라. 플레이어가 나중에
  "이 의심은 무엇 때문이었나"를 되짚을 수 있어야 한다.
  예) "알리바이 시각이 어긋남", "질문을 회피함", "다툰 사실을 인정함"
  진범을 지목하는 표현은 쓰지 마라.
```

이 값은 탐정 노트의 `비고` 열에 쌓인다.

## 4. Claude API 활용 기법

### 4.1 구조화 출력 (Structured Outputs)

`output_config.format`에 JSON Schema를 넣어 응답 형태를 강제한다. 프롬프트로
"JSON만 출력하라"고 부탁하는 방식보다 안정적이다.

```python
RESPONSE_SCHEMA = {
    "type": "object",
    "properties": {
        "narration": {"type": "string"},
        "choices": {"type": "array", "items": {
            "type": "object",
            "properties": {
                "label":  {"type": "string"},
                "action": {"type": "string", "enum": ["이동", "조사", "심문"]},
                "target": {"type": "string"},
            },
            "required": ["label", "action", "target"],
            "additionalProperties": False,
        }},
        "suspicion_delta": {...},
        "trust_delta":     {...},
        "change_note":     {"type": "string"},
    },
    "required": [...],
    "additionalProperties": False,
}
```

JSON Schema로는 표현할 수 없는 제약(정수 범위, 배열 길이)은 코드에서 처리했다.
`suspicion_delta`를 `-15~15`로 제한하는 것은 스키마로 불가능해서
`game_state._as_delta()`가 잘라낸다.

### 4.2 Prompt Caching — 브레이크포인트 2개

시스템 프롬프트(약 5,400자)는 매 턴 동일하므로 캐싱한다. 여기에 **누적 대화
히스토리도 캐싱**해서 턴이 늘어도 입력 비용이 선형으로 증가하지 않게 했다.

```python
system=[{"type": "text", "text": build_system_prompt(),
         "cache_control": {"type": "ephemeral"}}]          # 브레이크포인트 1

request_messages = history + [{"role": "user", "content": [
    {"type": "text", "text": user_text,
     "cache_control": {"type": "ephemeral"}}]}]             # 브레이크포인트 2
```

**함정이 있었다.** 브레이크포인트를 붙인 메시지를 그대로 히스토리에 저장하면
턴마다 브레이크포인트가 쌓여 최대 4개 제한을 넘는다. 그래서 **요청에만 붙이고
히스토리에는 평문으로 저장**한다. 5턴을 돌려 항상 2개로 유지되는 것을 확인했다.

### 4.3 스트리밍 — 미완성 JSON에서 나레이션만 추출

체감 대기가 문제였다(6절 참고). 응답 전체를 기다리지 않고 나레이션이 도착하는
대로 화면에 찍도록 스트리밍으로 바꿨다.

구조화 출력을 쓰면 스트림에 흐르는 것은 **미완성 JSON 문자열**이다.
스키마에서 `narration`이 첫 필드이므로, 정규식으로 그 값만 뽑아낸다.

```python
_NARRATION_RE = re.compile(r'"narration"\s*:\s*"((?:[^"\\]|\\.)*)')

def _partial_narration(buffer: str) -> str | None:
    match = _NARRATION_RE.search(buffer)
    if not match:
        return None
    try:
        return json.loads(f'"{match.group(1)}"')   # 이스케이프 복원
    except json.JSONDecodeError:
        return None                                # 잘린 순간엔 건너뛴다
```

`\n`, `\"`, `é`가 중간에 잘리는 경우까지 테스트했다. 실측: **첫 글자 7.1초,
전체 완료 13.6초, 화면 갱신 10회.**

### 4.4 누설 방지는 프롬프트가 아니라 구조로

GM에게 전달하는 상태 스냅샷에 원래 `unsearched_locations`(미발견 단서가 남은
장소 목록)가 들어 있었다. 선택지를 만들 때 필요했지만, 나레이션에서
"정원 쪽이 신경 쓰인다"처럼 흘릴 수 있는 정보였다.

프롬프트에 금지 조항을 넣는 대신 **정보 자체를 없앴다.**

```python
# 이전
snapshot["unsearched_locations"] = ["서재", "침실", "정원", "금고실", "다락방"]

# 이후 — 선택지 생성에 실제로 필요한 것은 이 하나뿐이다
snapshot["current_location_searchable"] = True
```

모델 출력에 의존하는 방어와, 정보를 주지 않는 방어는 신뢰도가 다르다.

### 4.5 출력 검증 3중 방어 (`gm._normalize`)

1. **잘못된 target 제거** — 존재하지 않는 장소(`지하실`)나 용의자(`D`)를 걸러낸다
2. **선택지 3개 미달 시 결정론적 보충** — 이동 선택지를 채운다
3. **소프트락 방어** — 이동은 턴을 소모하지 않으므로, 선택지 3개가 전부 이동이면
   턴이 영원히 흐르지 않는다. 최소 1개를 턴 소모 행동으로 강제한다.
   대체 심문 대상은 턴 번호로 순환시켜 진범으로 쏠리지 않게 했다

### 4.6 모델 설정

```python
anthropic.Anthropic(max_retries=2, timeout=60.0)

output_config={"effort": "medium",
               "format": {"type": "json_schema", "schema": RESPONSE_SCHEMA}}
max_tokens=8000
```

`effort`는 `low`와 `medium`을 비교해 나레이션 품질 때문에 `medium`으로 정했다.
`max_tokens`가 8000인 이유는 이 모델에서 **thinking과 응답 텍스트가 합산으로
상한에 걸리기** 때문이다.

## 5. AI로 만든 에셋

이미지 생성 AI나 음원 생성 AI를 쓰지 않았다. **AI가 코드를 작성해 결과물을
만들었다.** 라이선스가 깨끗하고, 수정이 필요할 때 파라미터만 바꾸면 된다.

### 5.1 삽화 — 손으로 쓴 SVG 15장

`assets/locations/*.svg`. 장소 7곳 + 평면도 + 사건 현장 도면 + 엔딩 2장 +
동기 시나리오 4장. 전부 2KB 미만의 벡터다.

테마 색상(`#14110f` 배경, `#d9a94a` 금색, `#8f2f28` 오xblood)을 그대로 써서
화면에 녹아든다. 평면도는 방마다 `id="room-*"`를 달아, 현재 위치를 강조할 때
**SVG 문서 안에 `<style>`을 끼워 넣는** 방식으로 처리했다.

```python
svg = svg.replace("</svg>",
    f"<style>#room-{slug}{{fill:#2a231d;stroke:{HIGHLIGHT}}}</style></svg>")
```

렌더링에 함정이 있었다. `st.html()`은 **`<svg>` 태그를 살균 과정에서 제거한다.**
`<style>`과 `<div>`는 통과하므로, SVG를 base64 data URI로 만들어
`background-image`로 넣었다.

### 5.2 사운드 — numpy 신호합성 5종

`tools/make_audio.py`(267줄)가 전부 생성한다. 22,050Hz 모노 16bit.

| 파일 | 소리 | 합성 방식 |
| --- | --- | --- |
| `rain.wav` | 폭우 배경음 (11.4초 루프) | 대역 성형 노이즈 3층 + 미세 물방울 5,200개 |
| `interrogate.wav` | 심문 · 메트로놈 (8초) | 감쇠 사인 + 클릭 트랜지언트, 강/약 교대 |
| `move.wav` | 이동 · 문 두 짝 (1.75초) | 걸쇠 딸깍 + 나무 공진 × 2 |
| `search.wav` | 조사 · 카메라 셔터 (0.95초) | 미러 업/셔터 닫힘 딸깍 + 필름 감김 |
| `clue.wav` | 단서 발견 · 종 (1.6초) | 비조화 배음 6개 |

기법 두 가지를 적어둔다.

**scipy 없이 필터 구현.** 주파수 영역에서 직접 곱한다. `1/f^alpha` 기울기에
저역/고역 통과를 걸어 대역을 만든다.

```python
spectrum = np.fft.rfft(RNG.standard_normal(count))
shape = 1.0 / np.power(freqs, alpha)                       # 기울기
shape *= 1.0 / (1.0 + (freqs / cutoff_hz) ** 2)            # 저역 통과
shape *= 1.0 / (1.0 + (highpass_hz / freqs) ** 4)          # 고역 통과
signal = np.fft.irfft(spectrum * shape)
```

**종은 배음 비율로 만든다.** 사인파를 2배·3배로 쌓으면 오르간이 된다.
실제 종의 부분음 비율(0.5 / 1 / 2 / **2.76** / **5.4** / **8.93**)로 쌓으면
종이 된다.

루프 이음새는 앞뒤 0.6초를 교차 페이드해서 없앴다(샘플 차 0.0004).

## 6. 개발 과정에서 실제로 겪은 문제와 수정

플레이테스트 → 원인 진단 → 수정 → 검증의 반복이었다. 헛짚은 것까지 적는다.

### 6.1 성능 — 한 턴이 5분 넘게 걸림

**증상.** 3턴에서 화면이 멈춘 것처럼 보여 새로고침.

**원인은 개발자(AI)가 만든 것이었다.** 앞서 529 과부하 오류를 겪고
`max_retries=6`, `timeout=120`으로 올려놨다. 실측하니 정상 응답은 **7초**인데,
과부하 구간에서 재시도가 붙으면 **40초·98초**가 나왔다. 6회 재시도 × 지수 백오프는
몇 분이 된다. 그 동안 화면은 조용히 멈춰 있다.

**수정.** ① `max_retries=2`, `timeout=60`으로 낮춰 빨리 실패하게 했다.
② 본질적 해결로 **스트리밍**을 붙여 글자가 도착하는 대로 찍히게 했다(4.3).

### 6.2 비 소리 — 두 번 헛짚음

1차는 고역 노이즈가 많아 **"이어폰 접촉 불량" 잡음**처럼 들렸다.
고치면서 물방울을 키우니 알갱이가 하나하나 들려 **ASMR**이 됐다.

실제 비는 초당 수천 개 충격이 겹친 "연속된 면"이다. 귀로만 판단하지 않고
**측정 지표**를 세워 잡았다.

| | 1차 | 2차 (ASMR) | 3차 |
| --- | --- | --- | --- |
| 저역 <300Hz | 잡음 | 85.7% | 0.1% |
| 중역 300Hz~3kHz | 얇음 | 6.8% | **71.2%** |
| 고역 >3kHz | 과다 | 7.4% | 28.8% |
| 크레스트 팩터 | — | — | **3.44** |

크레스트 팩터가 핵심이다. 3~4면 연속음, 6 이상이면 알갱이가 튄다.
물방울을 **5,200개로 늘리고 크기를 1/9로 줄여** 질감에만 기여하게 했다.
저역을 먹던 럼블 층은 제거했다.

파도 소리를 얹어봤지만 비의 질감을 흐려서 다시 뺐다.

### 6.3 이동 소리 — 두 번 다시 만듦

발소리로 시작했으나 저역에만 에너지가 있어 노트북 스피커에서 **거의 안 들렸다.**
중역을 얹으니 이번엔 **"노크 소리"** 가 됐다.

문 여는 소리로 바꿨는데, 0.72초짜리 경첩 스윕(220→380Hz + 17Hz 떨림)이
**사인파 신음**처럼 들렸다. 긴 음정 변화는 합성으로 자연스럽게 나오지 않는다.

최종은 **짧은 충격만** 남긴 것이다. 걸쇠 딸깍 + 나무 공진, 그리고 "문 두 짝"으로
늘려 방을 옮기는 느낌을 냈다(충격 시점 0.30초·1.26초로 분리 확인).

### 6.4 조사 소리 — 무슨 소리인지 모르겠다

종이 스치는 소리를 넣었으나 정체가 불분명했다. 탐정이 현장에서 하는 행동 중
소리가 가장 분명한 것은 **사진 촬영**이라 판단해 카메라 셔터로 바꿨다.
셔터는 ① 미러 업 ② 셔터 닫힘 ③ 필름 감김의 세 부분 구조가 있으면 바로
카메라로 들린다.

### 6.5 메모가 사라지는 버그 — AI가 만든 회귀

가장 오래 잡은 버그다. 개발자가 두 번 보고했다.

**1차 진단(틀림).** `st.tabs` → `st.segmented_control`로 바꿀 때 "선택된 면만
그리도록" 만든 것이 원인이라고 보고, 메모 값을 위젯이 아닌 딕셔너리에
미러링했다. **브라우저에서 여전히 사라졌다.**

**실제 원인.** Streamlit은 **어떤 회차에 그려지지 않은 위젯의 상태를 버린다.**
단서를 찾으면 단서 면으로 강제 이동하니, 그 순간 노트 위젯이 안 그려지고
메모가 폐기됐다. 딕셔너리 미러링으로는 위젯이 사라졌다 되살아나는 사이의
빈 순간을 막을 수 없었다.

**수정.** 원인을 없앴다 — **노트 위젯을 항상 그리고 보이기만 CSS로 감춘다.**

```python
if view != "탐정 노트":
    st.html("<style>.st-key-notes-pane{display:none !important;}</style>")
with st.container(key="notes-pane"):
    _render_notes()
```

**같은 원인으로 소리 설정도 깨지고 있었다.** 소리를 끄고 지목 화면으로 가면
토글이 사라져 상태가 폐기되고, 다음 회차에 기본값(켜짐)으로 되살아났다.
값을 위젯이 아닌 `sound_enabled`에 두고 토글에는 `value`로 넘겨 고쳤다.

### 6.6 "처음부터 다시" 버튼이 예외로 죽음

```
StreamlitAPIException: st.session_state.notes_A cannot be modified
after the widget with key notes_A is instantiated.
```

리셋 버튼이 메모 위젯보다 아래에 그려지므로 **누를 때마다 항상** 터졌다.
화면이 반쯤만 그려지고 멈추니 "기록이 사라진" 것처럼 보였다.
판 번호를 위젯 키에 넣어(`notes_1_C` → `notes_2_C`) 대입 없이 초기화하도록 고쳤다.

### 6.7 재시도가 엉뚱한 프롬프트를 보냄

API 오류 후 "다시 시도"를 누르면 **오프닝 프롬프트가 재전송**됐다.
히스토리의 마지막 항목으로 직전 요청을 되짚는 구현이었는데, `call_gm`은
성공할 때만 히스토리를 반환하므로 실패 시 되짚을 대상이 없었다.

턴과 단서는 이미 소모된 상태라 사이드바는 턴 1인데 나레이션은 도입부를
다시 묘사하는 상태가 됐다. 실패한 프롬프트를 `pending_input`에 보관해
그대로 재전송하도록 고쳤다.

### 6.8 성별을 전제한 단서 — 알 수 없는 정보로 추리 요구

정원 단서가 "굽이 얇은 **여성용** 구두"였는데, 플레이어는 용의자의 성별을 알
방법이 없었다. 두 방향으로 고쳤다.

- **인물 정보를 처음부터 공개** — 성별·나이·관계·**인상착의**·태도를 브리핑 표와
  게임 중 수사 기록에 노출
- **단서에서 성별 의존을 제거** — 발자국은 "비가 그친 뒤에 찍혔다"는 **시각**
  정보로 바꿨다. 성별로 좁히는 대신 알리바이와 대조해 좁힌다

같이 발견한 것이 있다. A의 신뢰도 70 이상 힌트가 "**여자** 구두 소리를 들었다"
였는데, 성별을 공개한 뒤로는 이것이 곧 C를 지목한다. "조심스러운 발소리"로
바꾸고 식별 정보를 덧붙이지 못하게 금지했다.

### 6.9 평판 점수 밸런스 결함 — 테스트가 잡음

첫 설계에서는 **2턴에 아무 단서 없이 진범을 찍으면 46점**이 나왔다.
속도 가산이 "수사하지 않기"를 보상하는 구조였다.

속도 가산을 **입증에 성공한 판에만** 주도록 고쳤다.

```
단서 없이 2턴에 찍기    20점
C단서 2개 + 정답       70점
전량 확보 + 2턴 남김    92점
```

### 6.10 그 외

| 문제 | 원인 | 수정 |
| --- | --- | --- |
| 인증 실패 시 같은 요청을 두 번 보냄 | `except TypeError`가 인증 오류까지 삼킴 | SDK 파라미터 오류만 잡도록 좁힘 |
| 델타에 문자열·`None`이 오면 크래시 | 검증 없이 `int()` | `_as_delta()`로 안전 변환 + clamp |
| 마지막 턴 오류가 조용히 사라짐 | 오류 여부와 무관하게 지목 화면으로 전환 | 지목 화면에 경고 배너 |
| 화면 전환 후 중간부터 보임 | Streamlit이 스크롤 위치를 유지 | JS로 맨 위로, `requestAnimationFrame` + 4회 지연 재시도 |
| 표 글자를 CSS로 못 키움 | `st.dataframe`은 캔버스 렌더 | 값이 고정된 표는 마크다운 표로 교체 |
| 사이드바가 DOM에 없음 | Streamlit 프로세스가 중복 실행 중 | 포트 점유 프로세스 정리 후 단일 실행 |
| `.ps1` 한글 깨짐 + 스크립트 오작동 | UTF-8 BOM 없이 저장 → ANSI로 읽힘 | BOM 추가 + 메시지를 영어로 |

## 7. 검증 방법

AI가 쓴 코드를 AI가 검증했다. 눈으로 보고 넘어가지 않도록 **측정 가능한 지표**를
세웠다.

| 대상 | 방법 |
| --- | --- |
| 게임 규칙 | `game_state.py` 단독 테스트 — 엔딩 4분기, 턴 예산, 델타 clamp, 중복 조사 방지 |
| UI 흐름 | **Streamlit `AppTest`** — 홈→브리핑→수사→지목→엔딩 완주, 위젯 상태, 버튼 타입 |
| LLM 출력 | 실제 API 호출로 층별 심문 검증, 스트리밍 부분 파서 단위 테스트 |
| 캐싱 | 5턴 동안 브레이크포인트가 2개로 유지되는지, 히스토리가 평문인지 |
| 오디오 | 대역별 에너지 비율, 크레스트 팩터, 루프 이음새 샘플 차, 클리핑 |
| 색상 | WCAG 명암비 직접 계산 (`#f2c14e` / `#14110f` = 11.2:1) |
| 실제 렌더 | 브라우저 DOM에 JS를 실행해 컬럼 폭·오디오 재생 상태·스크롤 위치 확인 |

`AppTest`의 한계도 만났다. 조건부로 렌더되는 위젯이 사라지면 하네스가 없어진
노드를 계속 붙들고 있어 `KeyError`로 죽는다. 그 경계를 넘는 검증은
브라우저에서 직접 했다.
