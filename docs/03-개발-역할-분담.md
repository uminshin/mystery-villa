# 개발 역할 분담 — 그날 밤, 별장에서

이 문서는 **개발 영역별로 무엇을 어떻게 구현했는지**를 정리한 것이다.
사람 이름 대신 역할 단위로 적었으므로, 팀원 배정 시 이 문서를 기준으로
담당을 나누면 된다.

각 영역은 **담당 범위 → 실제 구현 → 주요 판단**의 순서로 적었다.

---

## A. 게임 설계 (Game Design)

### 담당 범위
사건 구조, 단서 배치, 알리바이 설계, 턴 예산, 난이도, 평판 규칙.

### 실제 구현

- **사건 골격** — 폭풍으로 갇힌 외딴 섬의 별장, 용의자 3명, 장소 7곳, 15턴.
  진범은 개인 비서 C로 고정
- **단서 7개를 장소당 1개씩 배치.** 진범을 가리키는 것 4개, 레드헤링 3개
  (A 2개, B 1개)
- **알리바이를 3층 구조로 설계.** 같은 인물을 다시 심문하면 다음 층이 열린다.
  신뢰도 70 이상에서만 나오는 정보를 층마다 따로 두었다
- **추리 고리 설계** — "비가 23:20에 그쳤다"는 공개 정보 + "정원 젖은 흙의
  발자국" 단서 = C의 "23:00에 잤다"는 진술 붕괴. 단일 단서로는 못 풀고
  **공개 정보와 단서를 교차**해야 풀린다
- **레드헤링을 의도적으로 배치.** B는 신뢰도 70 이상에서 "23:40경 서재 쪽에서
  깨지는 소리를 들었다"고 실토하는데, 금고실에서는 들릴 거리가 아니다.
  알리바이는 거짓이지만 범인은 아니다. 세 사람 모두 거짓말을 하게 만들어
  "거짓말한다는 사실"만으로는 범인을 가릴 수 없게 했다
- **평판 점수 설계** — 판정 / 결정적 단서 수 / 단서 전량 확보 / 남긴 시간

### 주요 판단

**이동을 0턴으로.** 초기 10턴 설계에서 이동에도 턴을 쓰게 했더니, C 단서 2개를
찾는 데만 평균 8~10턴이 들어 심문할 여유가 구조적으로 사라졌다. 턴을
"의미 있는 행동" 단위로 재정의했다.

**10턴 → 15턴 확장.** 플레이테스트에서 "모든 용의자의 알리바이를 알지 못한 채
지목하게 된다"는 문제가 나왔다. 장소를 6곳→7곳(창고 추가)으로 늘리고
15턴으로 조정했다. 7곳 조사(7턴) + 세 사람 두 번씩 심문(6턴) = 13턴, 여유 2턴.

**속도 가산은 입증 성공한 판에만.** 초기 설계에서는 2턴에 아무 단서 없이
진범을 찍으면 46점이 나왔다. 수사하지 않는 쪽이 이득이 되는 구조여서
속도 가산에 조건을 걸었다.

## B. 게임 로직 / 백엔드 (`game_state.py`, 449줄)

### 담당 범위
상태 스키마, 규칙 판정, 데이터 정의, 점수 계산. **순수 함수만 둔다.**

### 실제 구현

```python
# 상태 스키마
{"turn": 0, "max_turns": 15, "location": "거실",
 "clues_found": [], "suspicion": {...}, "npc_trust": {...},
 "game_over": False, "ending": None}
```

- **결정론적 규칙 전담** — 턴 증가, 단서 발견, 엔딩 4분기, 평판 계산.
  LLM 출력에 좌우되지 않는다
- **데이터 테이블** — 용의자 3명(성별·나이·관계·인상착의·태도), 단서 7개,
  장소 7곳, 층 구조, 타임라인, 동기 시나리오 4절
- **입력 방어** — `_as_delta()`가 LLM이 보낸 델타를 `±15`로 자르고,
  문자열·`None`이 와도 0으로 떨군다
- **누설 없는 경고** — `weak_evidence_warnings()`는 진범 정보를 보지 않고
  "의심도 40 이상 + 그를 가리키는 단서 2개 미만"만 판정한다. A·B·C에
  같은 규칙이 걸리므로 경고 유무로 진범을 역산할 수 없다
- **층 구조와 이동 방향** — `move_direction()`이 두 장소 사이를
  "올라간다 / 내려간다 / 같은 층에서 옮긴다 / 밖으로 나간다"로 판정한다

### 주요 판단

**Streamlit·API 의존성을 두지 않았다.** 덕분에 이 모듈은 단독으로 테스트할 수
있고, UI를 몇 번 갈아엎는 동안 규칙 코드는 손대지 않았다.

**진범 정보의 노출 범위를 최소화.** `CULPRIT`은 이 모듈과 시스템 프롬프트에만
있다. 화면으로 나가는 상태 스냅샷에는 들어가지 않는다.

## C. LLM 통합 / 프롬프트 엔지니어링 (`gm.py`, 357줄)

### 담당 범위
Claude API 경계. 시스템 프롬프트, 구조화 출력, 스트리밍, 캐싱, 출력 검증.

### 실제 구현

- **시스템 프롬프트 약 5,400자** — 역할, 사건 개요, 공간 구조, 단서 표,
  타임라인, 알리바이 3층 표, 심문 규칙, 비공개 진실, 출력 규칙
- **구조화 출력** — `output_config.format`에 JSON Schema를 넣어
  `narration` / `choices` / `suspicion_delta` / `trust_delta` / `change_note`를 강제
- **Prompt caching 브레이크포인트 2개** — 시스템 프롬프트 + 매 턴 마지막 user
  메시지. 요청에만 붙이고 히스토리에는 평문으로 저장해 4개 제한을 넘지 않게 했다
- **스트리밍 + 부분 JSON 파서** — 미완성 JSON에서 `narration` 값만 정규식으로
  뽑아 실시간 표시. 이스케이프가 잘린 순간을 안전하게 건너뛴다
- **출력 검증 3중 방어(`_normalize`)** — 잘못된 target 제거, 선택지 3개 미달 시
  결정론적 보충, 전부 이동일 때 소프트락 방어
- **오류 분류** — 529/429(혼잡)를 다른 오류와 분리해 원인과 대처를 안내

### 주요 판단

**프롬프트로 막을 것과 구조로 막을 것을 구분했다.** 미발견 단서의 위치를
GM에게 알려주던 필드(`unsearched_locations`)는 금지 조항을 넣는 대신
**필드 자체를 없앴다.** 모델 출력에 의존하는 방어와 정보를 주지 않는 방어는
신뢰도가 다르다.

**나쁜 예를 프롬프트에 넣었다.** "플레이어가 모르는 정보를 쓰지 마라"만으로는
교정되지 않아, 실제로 나왔던 잘못된 선택지를 나쁜 예로 명시했다.

**반복 방지를 명시적으로 지시했다.** "같은 층을 두 번 반복하지 마라",
"같은 인물을 다시 심문하면 반드시 새 정보를 하나 준다".

## D. 프론트엔드 / UI (`app.py`, 969줄)

### 담당 범위
화면 구성, 상태 전환, 반응형 레이아웃, 애니메이션, 오디오·삽화 렌더.

### 실제 구현

- **5개 화면** — 홈 → 브리핑 → 수사 → 지목 → 엔딩
- **반응형 2단 배치** — 넓으면 무대(3) : 수사 기록(2)로 나란히, 좁아지면
  위아래로 쌓인다. `layout="wide"`로 본문 폭 제한(700px)을 풀었다
- **나레이션 스트리밍 표시** — 클릭 즉시 ① 효과음 재생 ② 지난 턴 단서 카드 제거
  ③ 선택지 버튼 제거 ④ 스트리밍 시작 순서로 처리
- **수사 기록 3면** — 용의자(수치 + 인상착의) / 단서 / 탐정 노트(자동 기록 + 메모).
  단서를 찾으면 단서 면으로 자동 이동
- **읽기 폭 제어** — 레이아웃은 넓게, 나레이션은 `max-width: 46rem`으로 좁게
- **테마** — `.streamlit/config.toml`로 색상·폰트·라운딩. 요소 단위 크기가
  필요한 곳만 `st.container(key=...)` + CSS

### 주요 판단

**Streamlit의 제약을 우회한 지점들.**

| 제약 | 우회 |
| --- | --- |
| `st.html`이 `<svg>`를 제거한다 | base64 data URI를 `background-image`로 |
| `st.tabs`는 리렌더 시 첫 탭으로 돌아가고 코드로 선택할 수 없다 | `st.segmented_control` + 상태를 직접 보관 |
| 스크롤 API가 없다 | JS + `requestAnimationFrame` + 4회 지연 재시도 |
| `st.dataframe`은 캔버스라 CSS로 글자를 못 키운다 | 값이 고정된 표는 마크다운 표로 |
| 그려지지 않은 위젯의 상태를 버린다 | 노트 위젯을 항상 그리고 CSS로만 감춘다 |

**오디오 요소의 위치를 고정했다.** 배경음 요소가 위치를 바꾸면 새 요소로
취급되어 매 턴 처음부터 다시 재생된다. 컬럼 밖 고정 키 컨테이너에 두어
턴을 넘겨도 끊기지 않게 했다.

## E. 아트 / 삽화 (`assets/locations/*.svg`, 15장)

### 담당 범위
장소 삽화, 평면도, 사건 현장 도면, 엔딩 및 시나리오 삽화, 색 설계.

### 실제 구현

| 분류 | 장수 | 내용 |
| --- | --- | --- |
| 장소 | 7 | 거실·서재·침실·정원·창고·금고실·다락방 |
| 평면도 | 1 | 층 구분, 문틈, 방별 가구 힌트, 현장 표시, 방위 |
| 사건 현장 | 1 | 서재 도면 — 쓰러진 자세, 둔기 위치, 흩어진 서류 |
| 엔딩 | 2 | 검거 / 미제 |
| 동기 시나리오 | 4 | 편지 · 통보 · 창고 · 그 후 |

- 전부 손으로 쓴 SVG. 파일당 2KB 미만
- 테마 색상만 사용 — 배경 `#14110f`, 크림 `#e8ddc8`, 금색 `#d9a94a`,
  오xblood `#8f2f28`, 강조색 `#f2c14e`
- 평면도는 방마다 `id="room-*"`를 달고, 현재 위치를 SVG 내부 `<style>` 삽입으로
  강조한다

### 주요 판단

**강조색을 계산으로 정했다.** "발견·변화"를 알리는 색이 필요했는데, 주색상
오xblood는 이미 "되돌릴 수 없는 결정"(지목)에 쓰고 있었다. 촛불 불꽃색
`#f2c14e`로 정하고 명암비를 확인했다 — 배경 대비 **11.2:1**(WCAG AA 기준의 두 배).

**초상화를 사건 현장 도면으로 교체.** 피해자 증명사진 형식으로 그렸더니
"무섭다"는 피드백을 받았다. 어디서 어떤 자세로 쓰러졌는지 보여주는 도면이
정보량도 많고 톤도 맞았다.

**엔딩 삽화의 의도를 수정.** 처음엔 사건 이후(검거 장면)를 그렸는데, 요구는
"동기 시나리오를 읽을 때 심심하지 않게"였다. 4절 각각에 **그날 밤의 장면**을
붙이는 방식으로 다시 그렸다.

## F. 사운드 (`tools/make_audio.py`, 267줄)

### 담당 범위
배경음·효과음 합성, 볼륨 균형, 재생 타이밍.

### 실제 구현

| 파일 | 소리 | 방식 |
| --- | --- | --- |
| `rain.wav` | 폭우 (11.4초 루프) | 대역 성형 노이즈 3층 + 미세 물방울 5,200개 |
| `interrogate.wav` | 메트로놈 (8초) | 감쇠 사인 + 클릭, 강/약 교대 |
| `move.wav` | 문 두 짝 (1.75초) | 걸쇠 + 나무 공진 × 2 |
| `search.wav` | 카메라 셔터 (0.95초) | 미러 업/셔터 닫힘 + 필름 감김 |
| `clue.wav` | 종 (1.6초) | 비조화 배음 6개 |

- scipy 없이 주파수 영역에서 직접 필터링
- 루프 이음새는 앞뒤 0.6초 교차 페이드(샘플 차 0.0004)
- 재생 타이밍 — 행동음은 **클릭 즉시**, 단서 발견음은 **나레이션이 끝난 뒤**

### 주요 판단

**귀로만 판단하지 않고 측정 지표를 세웠다.** 비 소리를 두 번 헛짚은 뒤,
대역별 에너지 비율과 **크레스트 팩터**(3~4면 연속음, 6 이상이면 알갱이가 튄다)를
기준으로 잡았다. 최종은 중역 71.2% / 크레스트 3.44.

**합성으로 가능한 것과 불가능한 것을 구분했다.** 빗소리·메트로놈·종·셔터는
합성으로 충분하다. 발소리·유리 깨짐처럼 실제 녹음이 필요한 소리는 포기하고
다른 소리로 대체했다(발소리 → 문 여는 소리).

**볼륨을 기준음에 맞춰 정규화했다.** 심문 메트로놈이 적당하다는 피드백을 받아
그것을 기준(peak 0.50)으로 조사(0.30)·이동(0.62)·배경음(0.40)을 재조정했다.

## G. QA / 검증

### 담당 범위
자동 테스트, 실제 API 검증, 브라우저 검증, 회귀 방지.

### 실제 구현

| 대상 | 방법 |
| --- | --- |
| 게임 규칙 | 단독 테스트 — 엔딩 4분기, 턴 예산, 델타 clamp, 중복 조사 방지 |
| UI 흐름 | **Streamlit `AppTest`** — 전체 완주, 위젯 상태, 버튼 타입, 탭 순서 |
| LLM 출력 | 실제 API로 층별 심문 3회 검증, 스트리밍 부분 파서 단위 테스트 |
| 캐싱 | 5턴 동안 브레이크포인트 2개 유지 / 히스토리 평문 확인 |
| 오디오 | 대역 에너지, 크레스트 팩터, 이음새, 클리핑 |
| 색상 | WCAG 명암비 계산 |
| 실제 렌더 | 브라우저 DOM에 JS 실행 — 컬럼 폭, 오디오 재생 상태, 스크롤 위치 |

### 주요 판단

**테스트가 실제로 버그를 잡았다.** 기록해 둘 만한 것들:

- 평판 점수 밸런스 결함(찍기가 46점) — 시나리오 테스트가 잡음
- "처음부터 다시" 버튼 소멸 — `AppTest`가 버튼 목록 비교로 잡음
- 재시도가 오프닝을 재전송 — 오류 주입 테스트로 재현
- 메모 유실의 실제 원인 — `AppTest`가 사라진 위젯에서 `KeyError`로 죽으며 드러남

**하네스의 한계도 기록했다.** `AppTest`는 조건부 렌더 위젯이 사라지면 없어진
노드를 붙들고 죽는다. 그 경계를 넘는 검증은 브라우저에서 직접 했다.

## H. 개발 인프라 / 도구

### 담당 범위
개발 편의 도구, 버전 관리, 환경 문제 해결.

### 실제 구현

- **`preview_ui.py`** — GM 호출을 고정 응답으로 갈아끼워 **API 비용 없이** UI만
  확인하는 하네스. 게임 중반 상태를 미리 넣어 수사 기록까지 채워진 화면을 본다
- **`theme.ps1`** — 테마 교체 + 서버 재시작을 한 번에. 포트 점유 프로세스와
  좀비 프로세스를 먼저 정리하고, 경로를 `$PSScriptRoot` 기준 절대 경로로 처리.
  세션에 API 키가 없으면 사용자 환경변수에서 끌어온다
- **`themes/`** — 테마 4종(candlelight 및 비교용 프리셋 3종)
- **Git** — 커밋 17개. `.gitignore`로 `__pycache__`, `secrets.toml`, `.env`,
  `*.log` 제외. **API 키가 저장소에 들어가지 않는 것을 커밋 전 전수 검사로 확인**

### 주요 판단

**환경 문제를 도구로 해결했다.** 개발 중 겪은 문제들:

| 문제 | 해결 |
| --- | --- |
| `streamlit` 명령을 못 찾음 | `Scripts` 폴더가 PATH에 없음 → `python -m streamlit` |
| 테마를 바꿨는데 반영 안 됨 | `config.toml`은 프로세스 시작 시 한 번만 읽힌다 → 재시작 |
| 재시작해도 옛 테마가 보임 | 이전 서버가 포트를 점유 → 스크립트가 먼저 정리 |
| `.ps1` 한글 깨짐 + 스크립트 오작동 | UTF-8 BOM 없이 저장하면 ANSI로 읽힌다 → BOM 추가 |
| 커밋에 로그 파일이 딸려 들어감 | 실행 중 서버가 파일을 잡아 삭제 실패 → `.gitignore`에 `*.log` |

**API 비용을 개발 단계에서 분리했다.** 테마와 레이아웃을 수십 번 바꿔보는 동안
`preview_ui.py`로 작업해 호출 비용이 발생하지 않았다.

## 팀 배정 시 참고

영역별 독립성과 선행 관계는 다음과 같다.

```
A 게임 설계 ──┬─→ B 게임 로직 ──┐
              │                 ├─→ D 프론트엔드 ─→ G QA
              └─→ C LLM 통합 ───┘
                                E 아트    (독립)
                                F 사운드  (독립)
                                H 인프라  (독립)
```

- **B(게임 로직)** 는 Streamlit·API 의존성이 없어 독립 작업이 가능하다
- **C(LLM 통합)** 는 B의 데이터 테이블에 의존한다
- **E(아트)·F(사운드)** 는 파일 규약만 맞추면 완전히 독립적이다
  (`assets/locations/<slug>.svg`, `assets/audio/<name>.wav`)
- **D(프론트엔드)** 가 가장 넓고, 다른 영역의 산출물을 조립한다
- 2인 팀이라면 `A+B+C` / `D+E+F` 로 나누고 `G+H`를 공유하는 것이 자연스럽다
