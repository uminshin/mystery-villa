# 그날 밤, 별장에서

미스터리 텍스트 어드벤처. Streamlit + anthropic SDK 직접 호출 (LangChain 없음).

## 실행

```bash
pip install -r requirements.txt
```

```bash
setx ANTHROPIC_API_KEY sk-ant-...
```

```bash
python -m streamlit run app.py
```

> 최초 1회 Streamlit이 `Email:`을 물어본다. 뉴스레터 구독 안내일 뿐이라 그냥 Enter로 비워두면 된다.
>
> `streamlit run app.py`로 바로 실행하면 이 환경에서는 `CommandNotFoundException`이 난다.
> `streamlit.exe`가 `%LOCALAPPDATA%\Python\pythoncore-3.14-64\Scripts`에 설치되는데
> 이 폴더가 PATH에 없기 때문이다. `python -m streamlit`은 PATH를 타지 않아 항상 동작한다.

## 다른 컴퓨터로 옮기기

기계에 묶인 것이 없다. DB도 없고 로컬 저장 파일도 없다(게임 상태는 `st.session_state`
메모리에만 있다). 폴더 전체가 50KB 미만이다.

옮긴 뒤 새 기계에서 할 일은 세 가지뿐이다.

1. Python 3.10+ 설치
2. `pip install -r requirements.txt`
3. `ANTHROPIC_API_KEY` 설정 — **키는 이 저장소에 없다.** 환경변수로만 주입한다.

| OS | 키 설정 | 실행 |
| --- | --- | --- |
| Windows | `setx ANTHROPIC_API_KEY sk-ant-...` (새 터미널 필요) | `python -m streamlit run app.py` |
| macOS / Linux | `export ANTHROPIC_API_KEY=sk-ant-...` (`~/.zshrc`에 추가) | `python -m streamlit run app.py` |

`theme.ps1`은 Windows PowerShell 전용이다. macOS/Linux에서는 테마 파일을 직접 복사하면 된다:

```bash
cp themes/candlelight.toml .streamlit/config.toml
```

어느 OS든 **테마를 바꾼 뒤에는 서버를 재시작**해야 한다. Streamlit은 `config.toml`을
프로세스 시작 시 한 번만 읽는다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `game_state.py` | 상태 스키마, 장소·단서 표, 턴/단서/엔딩 규칙 (결정론적) |
| `gm.py` | Claude API 호출. 시스템 프롬프트 + JSON 스키마 구조화 출력 |
| `app.py` | Streamlit UI. session_state로 상태 유지, 나레이션 + 버튼 3개 |

## 설계 메모

- **상태 권한은 Python에 있다.** LLM은 나레이션·선택지·의심도/신뢰도 델타만 제안하고,
  턴 증가·단서 발견·엔딩 분기는 `game_state.py`가 확정한다. 엔딩 조건이 모델 출력에
  흔들리지 않게 하려는 의도.
- **모델**: `claude-opus-5`, `effort: low` (짧은 응답 루프이므로), adaptive thinking 기본 on.
  `max_tokens`는 thinking + 텍스트 합산 상한이라 8000으로 여유를 뒀다.
- **구조화 출력**: `output_config.format`의 `json_schema`로 응답 형태를 강제.
  선택지 개수/target 유효성은 `gm._normalize()`에서 한 번 더 검증.
- **prompt caching**: 브레이크포인트 2개 — ① 시스템 프롬프트(진실 + 단서표, 고정)
  ② 매 턴 마지막 user 메시지. ②가 누적 히스토리를 캐싱해서 턴이 늘어도 입력 비용이
  선형으로 늘지 않는다. 단, 요청에만 붙이고 **히스토리에는 평문으로 저장**한다 —
  그러지 않으면 브레이크포인트가 턴마다 쌓여 4개 제한을 넘는다.
- **안전망**: 이미 조사한 장소에서는 `조사` 선택지를 `_normalize()`가 제거한다
  (프롬프트로도 지시하지만 모델 출력에 의존하지 않음). 잘못된 target도 여기서 걸러내고,
  선택지가 3개 미만이면 결정론적 이동 선택지로 보충한다.

## 단서 배치

| 장소 | 단서 | 가리키는 인물 |
| --- | --- | --- |
| 거실 | 엎어진 위스키 잔 두 개 | A |
| 서재 | 찢겨진 유언장 초안 | A |
| 침실 | 베개 밑의 편지 (서명 'C') | **C** |
| 정원 | 젖은 흙에 남은 발자국 | **C** |
| 금고실 | 위조된 채무 상환 계약서 | B |
| 다락방 | 반쯤 태운 사진과 빈 수면제 병 | **C** |

진범은 C 고정. C 단서가 3개인 이유는 정답 엔딩 조건이 "C 단서 2개 이상"이라
10턴 안에 도달 가능하게 하기 위함.

## 턴 규칙

| 행동 | 턴 비용 |
| --- | --- |
| 이동 | **0턴** |
| 조사 | 1턴 |
| 심문 | 1턴 |

플레이테스트 결과 이동까지 턴을 먹으면 10턴 안에 심문할 여유가 구조적으로 없었다
(C 단서 2개 확보에 이동·조사만 최소 4턴, 위치를 모르는 상태에서는 평균 8~10턴).
이동을 무료로 바꿔 턴을 "의미 있는 행동" 단위로 만들었다. 새 규칙에서는
**6곳 전부 조사(6턴) + 심문 3회(3턴) = 9턴**으로 완주 가능하다.

`_normalize()`가 선택지 3개 전부 이동이 되는 경우를 막는다 — 그대로 두면 턴이
영원히 흐르지 않아 지목 화면에 도달하지 못한다(소프트락).

## 알리바이 / 심문

시스템 프롬프트에 타임라인 + 용의자별 알리바이 표를 넣어 진술 일관성을 잡았다.

| 인물 | 주장 | 실제 |
| --- | --- | --- |
| A | 23:10 이후 침실에서 잤다 | 알리바이 없음. 유언장 변경을 이미 알고 있었다 |
| B | 23:00~23:50 금고실에 혼자 | 알리바이 거짓(깨지는 소리를 들었다고 실토). 서명 위조범이지만 살인범 아님 |
| C | 23:00에 자러 갔다 | 비가 23:20에 그쳤다 — 정원 발자국(c4)과 진술이 충돌 |

- 신뢰도 구간별 태도: `0~30` 적대적 / `31~69` 주장만 / `70~100` 숨긴 것까지 흘림
- 플레이어가 **이미 찾은 단서**를 들이대면 한 단계 더 실토한다. 못 찾은 단서는 언급조차 안 한다
- A·B는 둘 다 거짓말을 하지만 범인이 아니다 — 의심스러워 보이는 것이 이들의 역할
- C는 관계까지만 인정하고 살인은 어떤 상황에서도 자백하지 않는다

핵심 추리 고리: **비가 그친 시각(23:20)** + **정원의 젖은 흙 발자국** = C의 "잤다"는 진술 붕괴.

## 엔딩 분기

| 조건 | 엔딩 |
| --- | --- |
| C 지목 + C 단서 ≥ 2 | 정답 · 진실 |
| C 지목 + C 단서 < 2 | 미제사건 · 증거 불충분 |
| A 또는 B 지목 | 오답 · 잘못된 확신 |
| 지목 포기 | 미제사건 · 침묵 |
